# 5장. 스프링 데이터 JPA를 이용한 조회 기능

## 한 줄 요약

조회 기능은 **조회 전용 모델을 따로 두고, 검색 조건은 스펙 객체로 조합하는 것**이다.

## 학습 목표

- 변경 모델과 조회 모델(CQRS)을 분리하는 이유를 이해한다.
- 스펙이 무엇이고, 검색 조건을 스펙으로 조합하는 이유를 설명할 수 있다.
- 조회 결과를 정렬하고 페이징하는 방법을 이해한다.

## 1. CQRS 관점에서 본 조회

명령(변경) 모델과 조회 모델은 목적이 다르다.

변경은 애그리거트 단위로 규칙을 지켜야 한다. 루트를 조회하고, 루트의 기능으로 상태를 바꾸고, 리포지터리로 저장한다.

반면 조회는 여러 애그리거트의 데이터를 화면에 맞게 합쳐야 한다. 예를 들어 주문 목록 화면에는 주문 번호·상태(주문), 주문자 이름(회원), 상품명(상품)이 함께 필요하다. 애그리거트끼리는 ID로 참조하므로, 애그리거트 방식으로만 조회하면 주문·회원·상품을 따로 여러 번 조회해야 해서 느려진다. 게다가 조회는 상태를 바꾸지 않으므로 애그리거트가 지켜 주는 일관성 규칙도 필요 없다.

그래서 조회 기능은 애그리거트 리포지터리를 거치지 않고, 화면에 맞춘 조회 전용 모델을 따로 두어도 된다. 이렇게 명령과 조회의 책임을 나누는 것을 CQRS라고 한다.

## 2. 검색을 위한 스펙

### 스펙이란

스펙(Specification)은 **"이 대상이 조건을 만족하는가?"를 판단하는 검색 조건 하나를 객체로 만든 것**이다.

예를 들어 다음 조건들을 각각 하나의 스펙으로 만들 수 있다.

- 주문자가 user1인 주문
- 주문일이 1월 1일부터 1월 31일 사이인 주문
- 배송 준비 중 상태인 주문

### 스펙이 필요한 이유

검색 조건이 다양해지면 조건 조합마다 리포지터리 메서드를 만들어야 한다. "주문자로 검색", "주문자와 상태로 검색", "주문자와 기간으로 검색", "주문자와 상태와 기간으로 검색"처럼 조합의 수만큼 메서드가 늘어난다.

스펙을 쓰면 조건을 하나씩 만들어 두고, 필요한 것만 골라 조합해서 리포지터리에 넘기면 된다. 리포지터리는 "스펙을 받아 만족하는 대상을 찾는 기능" 하나만 제공하면 된다.

### 스펙 조합

스펙은 AND, OR, NOT으로 조합할 수 있다.

- "주문자가 user1" **AND** "주문일이 1월 중" → user1의 1월 주문
- "배송 준비 중" **OR** "배송 중" → 아직 배송이 끝나지 않은 주문

사용자가 검색 화면에서 일부 조건만 입력하는 경우에도, 입력된 조건에 해당하는 스펙만 골라 붙이면 되므로 검색 기능을 유연하게 만들 수 있다.

## 3. 정렬과 페이징

조회 결과는 보통 정렬하고, 한 번에 일부만 잘라서 보여 준다. 스프링 데이터 JPA는 쿼리를 직접 작성하지 않아도 리포지터리에 조건만 넘기면 이를 처리해 준다.

**정렬**

- 메서드 이름에 정렬 기준을 적는 방법과, 정렬 기준을 파라미터로 넘기는 방법이 있다.
- 정렬 기준이 많아지면 메서드 이름이 길어지므로 파라미터로 넘기는 편이 유연하다.

**페이징**

- "몇 번째 페이지를, 몇 개씩, 어떤 순서로" 가져올지를 파라미터로 넘긴다.
- 결과는 데이터 목록만 받거나, 전체 개수,전체 페이지 수까지 함께 받을 수 있다.
- 전체 개수를 함께 받으면 개수를 세는 쿼리가 한 번 더 실행된다. 전체 개수가 필요 없는 화면이라면 목록만 받아 불필요한 쿼리를 줄인다.

**상위 N개**

- "최근 주문 3개"처럼 앞에서부터 몇 개만 필요하면 개수를 지정해 조회할 수 있다.
