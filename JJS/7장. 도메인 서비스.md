# 7장. 도메인 서비스

## 한 줄 요약

도메인 서비스는 **한 애그리거트에 넣기 애매한 도메인 로직을 상태 없이 별도로 분리한 것**이다.

## 학습 목표

- 여러 애그리거트가 필요한 로직을 한 애그리거트에 넣으면 생기는 문제를 이해한다.
- 도메인 서비스가 무엇이고, 응용 서비스와 어떻게 다른지 설명할 수 있다.
- 외부 시스템 연동을 도메인 서비스로 표현하는 이유를 이해한다.
- 도메인 서비스를 어느 패키지에 두어야 하는지 설명할 수 있다.

## 1. 왜 필요한가

어떤 도메인 로직은 여러 애그리거트의 정보가 필요하다. 이런 로직을 특정 애그리거트 하나에 넣으면 그 애그리거트가 자기 책임이 아닌 일까지 떠안게 된다. 다른 애그리거트를 참조해야 하고, 관련 없는 정책이 바뀔 때도 코드를 고쳐야 한다.

→ 이런 로직은 애그리거트 밖의 **도메인 서비스**로 분리한다.

## 2. 도메인 서비스란

- 도메인 영역에 속하는 **도메인 로직**이다.
- 애그리거트,밸류와 달리 **상태가 없고 로직만** 가진다. 필요한 데이터는 파라미터로 받는다.
- 주로 쓰이는 경우
  - 여러 애그리거트가 필요하거나, 한 애그리거트에 넣기엔 복잡한 **계산 로직**
  - **외부 시스템 연동**이 필요한 도메인 로직
- 이름은 도메인 용어로 짓는다.

### 사용 방식

- 애그리거트 메서드에 도메인 서비스를 **파라미터로 넘기거나**, 도메인 서비스에 애그리거트를 넘겨 사용한다.
- 애그리거트에 도메인 서비스를 **필드로 주입하지 않는다.** 필드는 데이터를 담는 곳이고, 도메인 서비스는 특정 기능에서만 필요하기 때문이다.

### 응용 서비스와의 구분

> 판단 기준: 이 로직이 **애그리거트의 상태를 바꾸거나 상태 값을 계산하는가?**

- 그렇다면 도메인 로직이므로 → **도메인 서비스**
- 트랜잭션 처리처럼 흐름을 조율하는 일 → **응용 서비스**

## 3. 외부 시스템 연동

외부 시스템과의 연동도 도메인 관점에서 보면 하나의 도메인 로직이다. 예를 들어 "이 사용자가 권한을 가졌는가"를 다른 시스템에 물어봐야 한다면, 도메인 입장에서는 HTTP 호출이 아니라 **권한 확인**이라는 로직이다.

- 인터페이스는 **도메인 영역**에 도메인 용어로 정의한다.
- 실제 연동 구현은 **인프라스트럭처 영역**에 둔다.

## 4. 패키지 위치와 인터페이스

- 도메인 서비스는 관련된 **도메인 구성 요소와 같은 패키지**에 둔다. 개수가 많으면 하위 패키지로 나눠도 된다.
- 로직이 고정되어 있지 않거나 외부 시스템을 쓴다면 인터페이스(도메인 영역)와 구현(인프라 영역)을 분리한다. 그러면 도메인이 특정 구현에 묶이지 않고 테스트도 쉬워진다.
