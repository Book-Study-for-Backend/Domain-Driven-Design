# 1.1. 도메인이란?
- 도메인(Domain) : 소프트웨어로 해결하고자 하는 문제의 영역
	- 한 도메인을 여러 하위 도메인으로 구성할 수 있다.
- 도메인은 고정되어 있지 않다. 상황에 따라서 도메인 구성을 변경할 수 있어야 한다.
	- 기업의 규모, 업무 처리 방식은 모두 다르다. 동일한 규격을 사용할 수 도 있으나, 상황에 따라서 변화되어야 한다.

# 1.2. 도메인 전문가와 개발자 간 지식 공유
- 도메인은 소프트웨어로 정의한 영역에 대해서만 이야기 하는 것이 아니다.
	- 소프트웨어는 문제 해결을 위한 선택이고 좋은 개발자가 좋은 도메인 전문가는 아니다.
	- 각 도메인 전문가들의 요구사항을 바탕으로, 도메인 친화적인 기능을 추가해야한다.
- 도메인 친화적인 기능을 추가하기 위한 좋은 방법은 전문가와 개발자 간의 대화다.

# 1.3. 도메인 모델
- 도메인 모델 : 개발자와 전문가 간 이해를 확인하기 위한 다이어그램, 문서 등의 것.
	- 도메인을 이해할 수 있다면 표현 방식은 중요하지 않다.
- 도메인에 필요한 내용을 정의하고 모델을 만들면 관계자들 사이에 멘탈 모델을 일치시키기 수월하다.

# 1.4. 도메인 모델 패턴
- 도메인 모델 패턴은 [1.3]과 달리, "엔터프라이즈 애플리케이션 아키텍처 패턴" 책의 도메인 모델 패턴을 의미한다.
- 도메인 모델은 아키텍처 상의 도메인 계층을 객체 지향 기법으로 구현하는 패턴을 의미한다.
- 일반적인 어플리케이션 아키텍처는 아래의 표와 같다.

| 영역               | 설명                                                             |
| ---------------- | -------------------------------------------------------------- |
| 사용자 인터페이스(혹은 표현) | 사용자의 요청을 처리하고 사용자에게 정보를 보여준다. 사용자는 사람 뿐만이 아니라, 외부 시스템일 수 도 있다. |
| 응용               | 요청한 기능을 실행한다. 비즈니스 로직을 직접 구현하지 않으면서도 도메인 계층을 조합해서 기능을 실행한다.    |
| 도메인              | 시스템이 제공할 도메인 규칙을 구현한다.                                         |
| 인프라스트럭쳐          | DB, Message 등의 외부 시스템과의 연동을 처리한다.                              |

# 1.5. 도메인 모델 표출 
- 앞서 말한 것과 같이, 좋은 개발자는 좋은 도메인 전문가가 아니다. 요구사항을 이해하고 이를 바탕으로 코드를 만들어야 한다.
- 요구사항을 이해하게 된다면 클래스 간의 설계를 어떻게 세워야 하는지 찾아낼 수 있다.

# 1.6. 엔티티와 벨류
- 도출한 모델은 큰 범주에서 엔티티와 밸류로 나눌 수 있다.

## 1.6.1. 엔티티
- 엔티티의 가장 큰 특징은 식별자를 가진다는 점이다. 식별자를 통해서 엔티티 객체를 구별할 수 있다.
	- 이러한 식별자는 엔티티 객체마다 고유하다.

## 1.6.2. 엔티티의 식별자 생성
- 식별자 생성 시점은 도메인의 특징과 사용 기술에 따라서 달라진다. 아래의 방식을 참고할 수 있다.
	- 특정 규칙에 따른 생성(생성일자, 주문자 등)
	- UUID
	- 값을 직접 입력
	- 일력번호 사용

## 1.6.3. 밸류 타입
- 밸류 타입은 개념적으로 완전한 하나를 표현할 때 사용한다.
	- 코드 가독성 향상을 위해서 의미를 명확하게 표현하기 위해서 사용할 수 도 있다.
- 코드 관점에서 생각하자. 문제를 해결하기 위해 필요한 값들은 모두 다르다.
	- 10개의 정보를 넘겨야 할 일이 있다면 10개를 모두 넘기는 것 보다는 밸류 타입으로 선언해서 넘긴다. 이처럼 개념적으로 표현하는 바를 묶을 수 있다.
	- 값은 전송되면서 변화가 변경하면 전혀 다른 값이 나올 수 있으므로 밸류 타입은 불변 속성을 가진다.

## 1.6.4. 엔티티 식별자와 밸류 타입
- 엔티티의 식별자를 표현하기 위해서 주로 String 타입을 사용한다. 이때, 밸류 타입을 통해서 ID로 묶으면 해당 필드가 무엇인지 명확하게 표현할 수 있다.

# 1.7. 도메인 용어와 유비쿼터스 언어
- 코드 작성 시, 사용하는 용어는 무척 중요하다. 도메인 용어를 코드에 적용하면 코드의 의미를 해석하는 시간을 줄일 수 있다.
- 서로 통일된 언어의 중요함을 강조하기 위해 유비쿼터스 언어(Ubiquitous language)라는 용어를 사용한다.
	- 소통 과정에서 개발자<->기획자 간의 불필요한 오해를 줄이고 언어의 모호성을 낮출 수 있다.
- 시간이 지날수록 도메인 영역이 거대해지는데 새롭게 이해한 내용을 잘 표현할 수 있는 용어를 찾아내고 공통 용어로 만드는 과정을 거쳐야한다.
