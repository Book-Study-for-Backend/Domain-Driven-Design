# 3.1. 애그리거트
- 상위 수준 개념을 이용하여 전체 모델을 정리하면 전반적인 관계를 이해하는 데 도움이 된다.
	- 상위 수준 개념에 대한 이해 없이 세분화된 개념으로 도메인을 바라보면 복잡함에 이해하기 힘들다.
	- 또, 주요 도메인 요소 간의 관계를 파악하지 어렵다는 것은 코드 변경과 확장성을 낮추게 된다.
- 애그리거트를 통해 객체를 묶어 바라보면 상위 수준에서 도메인 모델 간 관계를 파악할 수 있다.
	- 애그리거트는 복잡한 도메인을 단순한 구조로 만들어준다.
- 애그리거트를 묶기 위해서는 서로 공통된 관심사를 가지고 있는 모델을 찾아야 한다. 
	- 주문에 사용되는 모델과 회원 관리에 사용되는 모델이 서로 같은 애그리거트로 묶이면 안된다.

# 3.2. 애그리거트 루트
- 애그리거트는 설계 단계에서 제공되는 도메인 모델의 논리 단위다. 애그리거트로 묶었으면, 애그리거트를 관리하고 실제로 구현 단계에서 유효하게 사용 할 수 있는 물리적 개념으로 만들 수 있어야 한다.
	- 이러한 것을 애그리거트 루트를 통해서 관리하고 애그리거트를 지속할 수 있다.

## 3.2.1. 도메인 규칙과 일관성
- 애그리거트 루트는 단순히 애그리거트에 속한 객체를 포함하는 것이 전부가 아니다.
	- 애그리거트에 속한 모델들이 도메인 규칙에 따라서 구현되고 사용될 수 있도록 일관성을 구현해야 한다.
- 일관성을 확보하기 위해서 애그리거트 외부에서 애그리거트에 속한 객체를 직접 변경하면 안된다.
	- 애그리거트 루트가 강제하는 규칙을 적용할 수 없어 모델의 일관성을 깨는 원인이 된다.
- 불필요한 중복을 피하고 애그리거트 루트를 통해서만 도메인 로직을 구현하게 만들자.

## 3.2.2. 애그리거트 루트의 기능 구현
- 애그리거트 루트는 애그리거트 내부의 다른 객체들을 조합해서 기능을 완성한다.
	- 애그리거트 루트는 구성요소의 상태만 참조하는 것이 아니라, 기능 실행을 위임하기도 한다.

## 3.2.3. 트랜잭션 범위
- 트랜잭션은 작으면 작을수록 좋다. 잠금 대상이 많아지면 동시에 처리할 수 있는 트랜잭션 개수가 줄어든다는 것을 의미하고, 이는 전체적인 성능 저하로 이어진다.
- 한 트랜잭션에서는 한 개의 애그리거트만 수정해야 한다.
	- 두 개의 애그리거트를 수정하게 된다면, 실행되는 트랜잭션은 스스로의 책임 이상의 것을 관리하게 된다.
	- 애그리거트는 서로에게 최대한 독립적으로 구현하며, 애그리거트 간의 결합도를 낮춰야 한다.
- 만약, 두 개의 애그리거트를 수정해야 한다면 응용 서비스에서 애그리거트의 상태를 변경하도록 하라.
	- 이러한 일은 팀 표준, 기술 제약, UI 구현의 편리 등 다양한 이유로 구현하게 될 수 있다.

# 3.3. 애그리거트와 리포지터리
- 애그리거트는 한 개의 도메인 모델을 표현하므로, 객체의 영속성을 처리하는 리포지터리는 애그리거트 단위로 존재한다.
	- 보통 리포지터리는 `save`, `findById`와 같은 메서드를 제공한다.


# 3.4. ID를 이용한 애그리거트 참조
- 애그리거트도 다른 애그리거트를 참조한다. 관리 주체는 애그리거트 루트이므로, 이는 다른 애그리거트 루트를 참조한다는 것과 동일하다.
	- 실제로 인스턴스를 보유하고 있으면 외부에서 애그리거트 루트의 상태를 변경하게 될 수 있다.
	- ID를 사용하여 간접 참조를 구현하자.
- ID를 통한 간접 참조를 사용하면 N+1 문제가 발생할 수 있는데, 데이터 조회를 위한 별도 DAO를 만들고 조회 메서드에서 Join을 사용해 한 번의 쿼리로 필요한 데이터를 가져오면 된다.
	- N+1 : 목록 조회를 1번 했을 때, 항목마다 1번씩 N번 조회를 하게 되는 문제

# 3.5. 애그리거트 간 집합 연관
- 애그리거트 간의 1-N, M-N 연관은 컬렉션을 이용한 연관이라고 불린다.
	- 1-N 관계 : 카테고리 입장에서 한 카테고리에 한 개 이상의 상품이 속할 수 있다.
	- N-1 관계 : 상품 입장에서 한 카테고리에만 속할 수 있다.
- 1-N 관계는 N의 개수에 따라서 실행 속도가 느려질 수 잇으므로, 실제 구현에 반영하지는 않는다.
	- 상품 입장에서 자신이 속한 카테고리를 N-1로 연관 지어서 구하면 된다.
- M-N 관계는 양쪽 애그리거트에 컬렉션으로 연관을 만든다.
	- M-N 관계 : 한 상품이 여러 카테고리에 속할 수 있다.
	- 실제 요구사항을 고려해서 M-N 연관을 구현에 포함시킬지 결정하면 된다.
