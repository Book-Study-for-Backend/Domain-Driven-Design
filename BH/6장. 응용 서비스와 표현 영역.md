# 6.1.  표현 영역과 응용 영역
- 응용 영역과 표현 영역은 사용자와 도메인을 연결하는 매개체 역할을 한다.
- 표현 영역은 사용자의 요청을 해석한다.
	- 사용자 영역에서 데이터를 전달하면 URL, 요청 파라미터, 쿠키, 헤더 등을 이용해서 기능을 판별하고 응용 서비스를 실행한다.
- 사용자 요청 기능을 제공하는 건 응용 영역에 위치한 서비스다.
	- 응용 영역의 서비스는 기능을 실행하고 실행 결과를 표현 영역으로 리턴한다.
- 응용 영역 파라미터와 표현 영역 데이터는 서로 형식이 일치하지 않다.
	- 표현 영역은 응용 영역이 요청하는 형식으로 사용자 요청을 변환한다.
	- 결과 반환 시 표현 영역은 실행 결과를 사용자에게 알맞은 형식으로 응답한다.
- 사용자와 상호작용은 표현 영역이 담당한다. 이로 인해서 응용 영역은 사용자의 요구사항을 이해할 필요가 없어진다.

# 6.2. 응용 서비스의 역할
- 응용 영역은 사용자의 요청 기능을 실행하는 주체다. 
	- 사용자 요청을 처리하기 위해 리포지터리에서 도메인 객체를 가져와 사용한다.
- 응용 영역은 도메인 객체를 사용해서 사용자의 요청과 트랜잭션에 대한 처리를 담당한다.
	- 표현 영역과 도메인 영역을 연결하는 창구 역할을 한다.
	- 주로 도메인 객체 간의 흐름을 제어한다.
- 응용 영역에서 도메인 로직을 일부 구현하게 된다면 코드 중복, 로직 분산 등 코드 품질에 안 좋은 영향을 줄 수 있다.

## 6.2.1. 도메인 로직 넣지 않기
- 도메인 로직이 분산되면 코드 품질에 문제가 생기므로, 도메인 영역에 위치해야 한다.
	- 첫번째로 코드 응집성이 떨어지게 된다. 도메인 로직이 분산되면, 로직을 파악하기 위해 여러 영역을 분석해야 한다.
	- 두번째로 여러 서비스에서 동일한 로직을 반복해서 구현할 가능성이 높아진다. 
- 소프트웨어가 가져야 할 중요한 경쟁 요소 중 하나는 변경 용이성인데, 변경이 어렵다는 것은 소프트웨어의 가치가 떨어진다는 것을 의미한다.

# 6.3. 응용 서비스의 구현
- 표현 영역과 도메인 영역을 연결하는, 응용 영역은 파사드 디자인 패턴과 유사한 역할을 한다.
	- 응용 영역의 서비스는 복잡한 로직을 수행하지 않기 때문에 구현이 어렵지 않다.

## 6.3.1. 응용 서비스의 크기
- 회원 도메인을 생각해 보자. 응용 영역의 서비스는 회원 가입, 회원 탈퇴, 암호 변경, 비밀번호 초기화 등의 기능을 구현하기 위해서 도메인 모델을 사용하게 되며, 아래 내용을 고려할 수 있다.
	- 한 응용 서비스 클래스에 회원 도메인의 모든 기능을 구현하기
		- 동일 로직에 대한 중복 코드를 제거할 수 있다는 장점이 있다.
		- 단, 클래스의 크기가 비대해진다는 것은 단점이다.
	- 구분되는 기능별로 응용 서비스 클래스를 따로 구현하기
		- 클래스 개수는 늘어나지만, 코드 품질을 일정 수준으로 유지하는 것에 도움이 된다.

## 6.3.2. 응용 서비스의 인터페이스와 클래스
- 인터페이스가 필요한 몇 상황이 있다. 그 중 하나는 구현 클래스가 여러 개인 경우다.
	- 구현 클래스가 다수 존재하거나 런타임에 구현 객체를 교체해야 할 때 인터페이스를 유용하게 사용할 수 있다.
	- 하지만, 런타임에 응용 서비스를 교체하는 경우가 드물고, 구현 클래스가 두 개인 경우도 드물다.
	- 인터페이스와 클래스를 따로 구현하면 소스 파일만 많아지고 구현 클래스에 대한 간접 참조가 증가해서 전체 구조가 복잡해진다.
	- 인터페이스가 명확하게 필요하기 전까지는 작성하지 않는 것을 고려할만하다.

## 6.3.3. 메서드 파라미터와 값 리턴
- 응용 영역의 메서드는 로직을 수행하기 위한 값을 도메인 영역으로부터 전달 받는다.
	- 응용 영역의 수행 결과를 표현 영역에 전달하는 건 객체 및 애그리거트를 전달할 수 있다.
	- 표현 영역은 전달 받은 결과에서 필요한 값을 기반으로 사용자에게 전달할 수 있다.

## 6.3.4. 표현 영역에 의존하지 않기
- 응용 영역의 파라미터 타입을 결정할 때 주의할 점은 표현 영역과 관련된 타입을 사용하면 안된다는 점이다.
	- 응용 서비스만 단독으로 테스트하기 어렵고, 표현 영역의 변경과 같이 움직이게 된다.
	- 또, 응용 영역이 표현 영역의 역할까지 대신하는 상황이 발생할 수 도 있다.

## 6.3.5. 트랜잭션 처리
- 회원 가입에 성공했지만, DB에 회원 정보를 삽입하지 않으면 고객은 로그인 할 수 없다.
	- 트랜잭션을 통해서 데이터 정합성을 챙길 수 있으니, 적극 사용하는 것이 좋다.
	- 트랜잭션을 담당하는 건 응용 영역의 중요한 역할 중 하나이다.

# 6.4. 표현 영역
- 표현 영역의 책임은 크게 다음과 같이 나뉜다.
	- 사용자가 시스템을 사용할 수 있는 흐름을 제공하고 제어한다.
	- 사용자의 요청을 응용 영역에 전달하고 결과를 사용자에게 전달한다.
	- 사용자의 세션을 관리한다.

# 6.5. 값 검증
- 값 검증은 표현 영역과 응용 영역 두 곳에서 모두 수행할 수 있다.
	- 원칙적으로는 응용 영역에서 처리한다.
- 표현 영역에서 필수 값과 값의 형식을 검사하면, 응용 영역은 ID 중복 여부와 같은 논리적 오류를 검사하면 된다.
	- 즉, 영역마다 검사하는 조건을 다르게 설정해서 처리할 수 있다.
- 응용 영역의 서비스에서 값을 얼마나 엄격히 검증해야 하는지는 의견이 나뉜다.
